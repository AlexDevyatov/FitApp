# SnapMeal (FitApp) — splash screen: анализ темы и варианты

Обзорный лист: [variants-sheet.png](variants-sheet.png). Восемь полноразмерных вариантов
(1080×1920): `v1-ring-on-paper.png` … `v8-snapmeal.png`. Промпты лежат рядом
(`*.prompt.txt`), генератор — [generate.ps1](generate.ps1), сборка листа — [build_sheet.py](build_sheet.py),
вектор диафрагмы — [make_shutter_vector.py](make_shutter_vector.py).

**Выбран вариант 7** — «Полдень с затвором»: градиент из варианта 6, но герой не кольцо,
а диафрагма камеры.

**В 0.2.1 приложение переименовано в SnapMeal.** Финальный ассет —
[v8-snapmeal.png](v8-snapmeal.png): та же композиция с новой надписью. Варианты v1–v7
оставлены как история направления (на них ещё старое имя). В приложении надпись не
картинкой: её рисует Compose шрифтом Manrope, поэтому в APK имя берётся из `app_name`.

## 1. Что говорит тема приложения

### 1.1 Роли, которые видит пользователь

Тема задана дважды: как контракт в [`design/tokens.json`](../design/tokens.json) и как код
в [`Theme.kt`](../app/src/main/java/ru/fitapp/ui/theme/Theme.kt). Dynamic color выключен
намеренно — бренд держится на паре изумруд/крем.

| Роль | Светлая | Тёмная | Смысл | Где живёт в UI |
|---|---|---|---|---|
| `background` | `#F4F1E8` | `#101613` | тёплая бумага / ночной графит | фон всех экранов |
| `surface` | `#FFFFFF` | `#181F1B` | карточки-острова | карточки, панели |
| `primary` | `#0E6B4F` | `#7FD8B0` | **действие и прогресс** | кнопки, кольцо, активная вкладка |
| `secondary` | `#C8F26A` | `#C8F26A` | **цель достигнута** | маркер, галочка, «в пределах» |
| `tertiary` | `#FFB77D` | `#FFB77D` | **мало данных / внимание** | бейдж «мало данных» |
| `onBackground` | `#17211C` | `#E3EAE4` | чернильный текст | заголовки, числа |
| `onSurfaceVariant` | `#53645C` | `#B7C5BC` | тихие подписи | подписи, метаданные |

Правила, которые тема объявляет прямым текстом (README редизайна, §2): изумруд — только
действие и прогресс, **лайм — не больше 10 % площади экрана**, персик — не декор.
Гарнитура — Manrope, скругления 22–28 dp, кольцо калорий 220 dp при штрихе 14 dp
(`components.calorieRing`).

### 1.2 Контраст (WCAG, посчитано по токенам)

| Пара | Отношение | Вердикт |
|---|---|---|
| `#17211C` на `#F4F1E8` | **14.63 : 1** | текст любого размера |
| `#E3EAE4` на `#101613` | **14.97 : 1** | текст любого размера |
| `#7FD8B0` на `#101613` | **10.78 : 1** | акцент в тёмной теме |
| `#FFFFFF` на `#0E6B4F` | **6.49 : 1** | белая надпись на изумруде — можно |
| `#0E6B4F` на `#F4F1E8` | **5.75 : 1** | дуга/текст на бумаге — можно |
| `#53645C` на `#F4F1E8` | **5.56 : 1** | подпись проходит AA |
| `#C8F26A` на `#0E6B4F` | **5.06 : 1** | лайм читается на изумруде |
| `#0E6B4F` на `#C8F26A` | **5.06 : 1** | и наоборот |
| `#FFB77D` на `#0E6B4F` | **3.81 : 1** | ❌ текст нельзя, только маркер/точка |

Вывод для splash: **текст — только чернильный на бумаге, белый на изумруде или светлый
на тёмном фоне**. Персик на изумруде как надпись не проходит AA — в вариантах он либо
не используется, либо остаётся размытым пятном фона (v6).

### 1.3 Характер: три вещи, которые делают «FitApp»

1. **Один герой на экран.** На «Сегодня» это кольцо с крупным числом, на съёмке — кадр.
   Splash обязан подчиняться тому же закону: один смысловой элемент.
2. **Тишина вокруг героя.** Много пустого поля, тихие подписи, никакого декора.
3. **Цвет как семантика.** Изумруд = «работает / прогресс», лайм = «хорошо / цель».
   Поэтому в splash лайм — это **точка на дуге**, а не заливка фона (единственное
   исключение — экспериментальный v4).

### 1.4 Главная находка: тема и система уже разошлись

| Что | Сейчас | Проблема |
|---|---|---|
| `res/values/colors.xml` | `#2E7D32`, `#1B5E20`, `#8BC34A`, `#FAFAFA` | старая палитра, к новой теме отношения не имеет |
| `windowBackground` | `#FAFAFA` | при холодном старте — серо-белая вспышка, потом Compose красит крем/графит |
| `statusBarColor` | `#1B5E20` | не совпадает ни с `primary`, ни с фоном |
| `MainActivity.onCreate` | `enableEdgeToEdge()` + пустой `CircularProgressIndicator`, пока читается `onboardingCompleted` | пользователь видит системный «пропеллер» вместо бренда |
| Тема в настройках | светлая / тёмная / системная (`SettingsStore.darkThemeMode`) | splash должен следовать хотя бы системному night-mode |

Splash здесь — не украшение, а **шов между системным окном и Compose**. Если фон splash
не равен `background` темы, шов видно как мигание. Именно поэтому основная пара вариантов
строится на `#F4F1E8` и `#101613`, а не на изумруде.

## 2. Правила, выведенные из темы (применены ко всем вариантам)

1. Фон splash = `background` темы (крем или графит), не `primary`.
2. Один герой: кольцо калорий (продолжение главного компонента) **или** глиф диафрагмы
   (продолжение главного действия — съёмки).
3. Лайм — только маркер цели: точка на конце дуги, тонкая линия прогресса.
4. Текст: `FitApp` + одна строка `Дневник питания по фото` — уже существующая подпись
   приложения (`settings_about_note` в `strings.xml`), ничего нового придумывать не нужно.
5. Никакого спиннера-пропеллера: индикатор ожидания — сама дуга кольца.
6. Композиция по центру, симметрия, поля не меньше 15 % кадра.
7. Шрифт — Manrope; в продакшене надпись рисуется Compose/шрифтом, а не картинкой.

## 4. Рекомендация: выбран v7

**Берём v7 — «Полдень с затвором».** Причины, почему он сильнее остальных именно для FitApp:

1. **Герой честнее.** Приложение начинается с того, что человек фотографирует еду. Кольцо
   калорий на старте — это всегда 0 %: пустое кольцо читается как «ничего не съедено»,
   то есть ложный сигнал ещё до первого экрана. Затвор — это про действие, которое
   пользователь пришёл совершить.
2. **Один кадр вместо двух экранов.** Глиф диафрагмы — тот же силуэт, что у иконки
   [v4-01-shutter-mint](../icons/v4-01-shutter-mint/), у `ic_launcher_foreground` и у
   системного splash. Пользователь видит: иконка в лончере → иконка в системном splash →
   тот же затвор в брендированном слое. Ни одной новой сущности.
3. **Expressive без пестроты.** Градиент даёт настроение, но единственное цветное пятно,
   кроме фона, — лайм в углу. Персик работает как свет, а не как смысловой маркер,
   поэтому правило «лайм ≤ 10 %» и контрастные ограничения не нарушены.
4. **Совместим с механикой Android 12+.** Глиф плоский, без обводок, симметричный —
   одинаково хорошо режется круглой маской и живёт в 48 dp на иконке.

Резервы, если понадобится другой тон:

- **v1 / v3** — максимально незаметный переход (фон = `background` темы, кольцо).
- **v2** — системный splash и лончер (сплошной изумруд, мятный глиф).
- **v4** — только промо (стор, соцсети).
- **v5** — редакционный минимализм, если захочется уйти от камеры.
- **v6** — тот же «Полдень» с кольцом, оставлен для сравнения.

Практичная схема запуска: **системный splash = сплошной `#0E6B4F` + мятный глиф (v2),
сразу за ним Compose-слой = градиент + тот же глиф + логотип (v7).** Пользователь видит
один непрерывный кадр: иконка → она же на градиенте → приложение.

## 5. Движение и тайминг

Из `tokens.json` (`motion`): `short 180`, `medium 260`, `ring 600`, easing
`cubic-bezier(0.2, 0, 0, 1.0)`.

| Шаг | Длительность | Кривая |
|---|---|---|
| Лепестки диафрагмы доворачиваются на 60° — затвор «открывается» | 600 мс | `0.2, 0, 0, 1` |
| Мята расходится по лепесткам от центра к краю (fade цвета) | 260 мс, старт на 200 мс | linear |
| Логотип и подпись, fade + 8 dp вверх | 260 мс, старт на 120 мс | `0.2, 0, 0, 1` |
| Уход: fade всего слоя | 180 мс | linear |

Для кольцевых вариантов (v1 / v3 / v6) вместо поворота — дуга 0 → 75 % за те же 600 мс.

Предел системного `windowSplashScreenAnimationDuration` — 1000 мс; больше держать нельзя,
пользователь считает это зависанием. Если данные читаются дольше — затвор просто остаётся
открытым (для кольца — дуга замирает на 100 %), без «прыжка» вперёд-назад.

## 6. Как это внедрять

Сейчас splash в проекте нет: `Theme.FitApp` сразу стартует с `windowBackground #FAFAFA`.

### 6.1 Два слоя, потому что градиент системе не положить

`windowSplashScreenBackground` принимает только цвет. Значит v7 собирается из двух слоёв,
которые должны стыковаться без шва:

| Слой | Что показывает | Чем задаётся |
|---|---|---|
| системный, пока читается `onboardingCompleted` | `#0E6B4F` + мятный затвор | `windowSplashScreenBackground`, `windowSplashScreenAnimatedIcon` |
| брендированный Compose | градиент, затвор, логотип, подпись | `@Composable` в `MainActivity` поверх |

Шов незаметен, если затвор в обоих слоях одного размера и в одной точке: диаметр 40 % ширины
экрана, центр — оптический центр (не геометрический: группа «глиф + логотип + подпись»
оптически центрируется, поэтому сам глиф стоит выше середины).

### 6.2 Шаги

1. Зависимость: `implementation("androidx.core:core-splashscreen:1.0.1")`
   (нативная реализация на API 31+, бэкпорт на 26–30; AppCompat не требуется).
2. Ресурсы: `@color/splash_background` = `#0E6B4F`; `@drawable/ic_splash_shutter` — вектор
   диафрагмы, вписанный в безопасную зону.
3. Темы:

```xml
<style name="Theme.FitApp.Splash" parent="Theme.SplashScreen">
    <item name="windowSplashScreenBackground">@color/splash_background</item>
    <item name="windowSplashScreenAnimatedIcon">@drawable/ic_splash_shutter</item>
    <item name="windowSplashScreenAnimationDuration">600</item>
    <item name="postSplashScreenTheme">@style/Theme.FitApp</item>
</style>
```

4. `MainActivity`: `installSplashScreen()` до `super.onCreate`, затем
   `setKeepOnScreenCondition { onboardingCompleted == null }` — и удалить голый
   `CircularProgressIndicator` из `FitAppRoot`, он больше не нужен.
5. Почистить `colors.xml`: старые `#2E7D32 / #1B5E20 / #8BC34A / #FAFAFA` заменить на роли
   темы (`splash_background`, `primary`, `secondary`), `windowBackground` — на `background`.
6. Глиф: вектор 108×108, содержимое в центральных 66×66 (то же правило, что для adaptive icon).
   **Просветы между лепестками на градиенте должны быть прозрачными, а не залитыми тёмным:**
   в растре модель рисует их цветом фона, в Compose это один path с `fillType="evenOdd"`,
   иначе на градиенте появятся тёмные клинья.
7. Светлая тема: `splash_background` для v7 не нужен — изумруд одинаков в обеих темах.
   Но если пользователь выбрал светлую тему на тёмной системе, системный splash всё равно
   будет по системному night-mode (приложение узнаёт настройку только после чтения
   DataStore). Для v7 это не страшно: фон-изумруд не конфликтует с обоими режимами.

Чего избегать: градиента в `windowSplashScreenBackground` (не поддерживается), текста
на растре (надпись рисуется шрифтом Manrope), обводок у глифа (в 48 dp заплывают).

## 7. Файлы и перегенерация

```
splash/
  variants-sheet.png         обзорный лист 8 вариантов
  v1..v8-*.png               изображения 1080×1920
  v1..v8-*.prompt.txt        промпт каждого варианта
  _style.txt                 общий стилевой слой
  _negative.txt              negative prompt
  _shutter-vector-preview.png  как выглядит вектор диафрагмы в 1080 px
  generate.ps1               перегенерация: powershell -ExecutionPolicy Bypass -File .\splash\generate.ps1 -All
  build_sheet.py             пересборка листа: python splash\build_sheet.py
  make_shutter_vector.py     пересчёт вектора: python splash\make_shutter_vector.py
```

Модель — `qwen-image-3.0-pro` (через скилл `text-to-image`), размер `1080*1920`, `n=1`.
Важно: `generate.ps1` специально написан ASCII-only, а все русские файлы читаются
с `-Encoding UTF8` — Windows PowerShell 5.1 иначе декодирует их как ANSI и отправляет
в модель мусор (это уже случилось на первом прогоне).

Картинки — концепт-направление, а не готовые ассеты: геометрия перерисована вектором
(`ic_splash_shutter.xml`, генератор — `make_shutter_vector.py`), а надпись в приложении
рисует Compose шрифтом Manrope. Для кольцевых вариантов, если понадобятся, брать 220 dp
и штрих 14 dp из `tokens.json`, иначе на плотных экранах толщина «плывёт».
