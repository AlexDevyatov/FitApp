# FitApp — редизайн интерфейса

Концепт визуального языка и макеты всех экранов FitApp по гайдлайнам **Material Design 3
(Expressive)**. Макеты лежат в [`design/mockups/`](mockups), интерактивная презентация —
в [`design/index.html`](index.html), токены для внедрения — в
[`design/tokens.json`](tokens.json).

> Макеты сгенерированы моделью `qwen-image-3.0-pro` по единому стилевому промпту
> (скрипт — [`design/generate.py`](generate.py)). Это концепт-направление: точные
> формулировки, размеры и поведение заданы в этом документе и в `tokens.json`,
> а не «считаны» с картинки.

---

## 1. Идея

Нынешний UI — это набор Material-компонентов по умолчанию: тема из двух цветов,
плотные карточки, канцелярские заголовки, интерфейс «как из туториала». Пользователь
открывает приложение несколько раз в день на 5–10 секунд: сфотографировать еду,
посмотреть, сколько осталось, вечером прочитать отчёт. Значит, интерфейс должен
отвечать на три вопроса моментально: **сколько я уже съел**, **что я ел**, **что делать
дальше**.

Новый язык — «спокойная энергия»:

- **Тёплая бумага вместо белого холста.** Кремовый фон `#F4F1E8` снижает
  «больничность» белого и делает фотографии еды теплее.
- **Один сильный акцент.** Глубокий изумрудный `#0E6B4F` отвечает за действие и
  прогресс; лаймовый `#C8F26A` — только за «хорошо/цель», не для декора.
- **Крупные числа, тихие подписи.** Калории и макросы — главные герои, всё
  служебное уходит в `onSurfaceVariant` и уменьшается.
- **Карточки-острова.** Радиус 24–28 dp, мягкая тень, 20 dp внутреннего воздуха:
  каждый блок читается как отдельная мысль.
- **Материальные формы M3.** Filled-кнопки, сегментированные переключатели,
  навигационная панель с пилюлей-индикатором, large top app bar.

### Принципы

| Принцип | Что это значит на практике |
|---|---|
| **Сначала цифра** | Энергия дня — самый крупный элемент экрана. Макросы — второй уровень. |
| **Один экран — одно действие** | «Сегодня» ведёт к съёмке, «Календарь» — к дню, «Отчёт» — к выводу. |
| **Тишина вокруг важного** | Не больше 3 акцентных пятен на экран; остальное — поверхности и текст. |
| **Состояние видно всегда** | Статус карточки (ждёт, в обработке, готово, ошибка) — цвет + подпись + иконка. |
| **Дружелюбная ошибка** | Ошибка объясняет, что случилось и что нажать; никогда не показывает стектрейс. |

## 2. Цвет

Схема собрана под светлую и тёмную тему. Все роли — из Material 3 Color Roles,
поэтому `MaterialTheme.colorScheme` сразу даёт правильные пары «контейнер/на-контейнере».

### Светлая тема

| Роль | Hex | Где использовать |
|---|---|---|
| `background` | `#F4F1E8` | Фон экранов, тёплая бумага |
| `onBackground` | `#17211C` | Основной текст |
| `surface` | `#FFFFFF` | Карточки, поля, навигационная панель |
| `surfaceContainerLow` | `#FAF8F1` | Чипы, вложенные блоки, поля ввода |
| `surfaceVariant` | `#E9E5D9` | Разделители, трек прогресса, скелетоны |
| `primary` | `#0E6B4F` | Главная кнопка, прогресс, активная вкладка |
| `onPrimary` | `#FFFFFF` | Текст на изумрудном |
| `primaryContainer` | `#CDEBDD` | Мягкий акцент, плашки «хорошо» |
| `onPrimaryContainer` | `#002117` | Текст на мягком акценте |
| `secondary` | `#C8F26A` | Лаймовый маркер цели, галочки, «в пределах» |
| `onSecondary` | `#243300` | Текст на лайме |
| `secondaryContainer` | `#DFF5B4` | Фон чипа «готово» |
| `tertiary` | `#FFB77D` | Предупреждение «мало данных» |
| `onTertiary` | `#4A2600` | Текст на персиковом |
| `error` | `#BA1A1A` | Ошибки обработки |
| `errorContainer` | `#FFDAD6` | Баннер ошибки |

| `outlineVariant` | `#DCE3DD` | Тонкие разделители |
| `onSurfaceVariant` | `#53645C` | Вторичный текст, подписи |

Служебные цвета вне схемы: янтарный `#EF8A00` — «мало данных» в календаре и отчёте,
нейтральный `#B9B7AE` — пустой день.

| Роль | Hex |
|---|---|
| `background` | `#101613` |
| `surface` | `#181F1B` |
| `surfaceContainerLow` | `#1F2722` |
| `primary` | `#7FD8B0` |
| `onPrimary` | `#003825` |

узнаваем по изумрудно-кремовой паре.

## 3. Типографика

Гарнитура: **Manrope** (кириллица, геометричная, хорошо держит крупные числа),
fallback — `Roboto`. Числа — с табличными цифрами (`tnum`) и `-0.02em` трекингом,
чтобы «1 640» не прыгало при обновлении.

| Стиль | Размер / интерлиньяж | Начертание | Применение |
|---|---|---|---|
| `displayLarge` | 57 / 64 | 700 | Большое число в hero-кольце (на 2 строки не переносить) |
| `headlineLarge` | 32 / 40 | 700 | Заголовок экрана («Сегодня», «Календарь») |
| `headlineMedium` | 28 / 36 | 700 | Сумма в карточке блюда, вердикт отчёта |
| `titleLarge` | 22 / 28 | 600 | Заголовок секции |
| `titleMedium` | 16 / 24 | 600 | Заголовок карточки, имя блюда |
| `bodyLarge` | 16 / 24 | 400 | Основной текст |
| `bodyMedium` | 14 / 20 | 400 | Описания, элементы списка |
| `labelLarge` | 15 / 20 | 600 | Кнопки, вкладки |
| `labelMedium` | 12 / 16 | 500 | Чипы, бейджи |
| `labelSmall` | 11 / 16 | 500 | Подписи статусов, легенда |

Правила: заголовок экрана — один; подзаголовок — `bodyMedium` в `onSurfaceVariant`;
не использовать CAPS для русских слов (кроме аббревиатур Б/Ж/У); минимальный
кегль — 11 sp, максимальный — 57 sp.

## 4. Форма, сетка, движение

- **Сетка:** 4 dp базовая, 8 dp ритм; боковые поля экрана — 20 dp; между карточками — 12 dp;
  между секциями — 24 dp; внутренние поля карточки — 20 dp.
- **Радиусы:** карточка — 24 dp, hero-карточка — 28 dp, фото — 20 dp, поля и кнопки — 16–18 dp,
  чипы — full, bottom sheet — 28 dp сверху.
- **Тени:** `0 2 8 rgba(23,33,28,.06)` для карточек, `0 12 32 rgba(14,107,79,.14)`
  для hero и FAB. В тёмной теме теней нет — вместо них тональные поверхности.
- **Иконки:** линейные, 24 dp, толщина 1.8; в активном состоянии — filled.
- **Движение:** 200–300 ms, `FastOutSlowIn`. Кольцо калорий анимируется 600 ms.
  Переход «карточка → блюдо» — общий элемент (фото), 300 ms. FAB → камера — scale+fade.
  При `prefers-reduced-motion` / отключённой анимации в системе — без shared element.

## 5. Компоненты

### CalorieRing (новый)
Кольцо 220 dp, трек 14 dp `surfaceVariant`, прогресс — градиент `primary → secondary`,
круглые концы. В центре — `displayLarge` (калории), под ним `bodyMedium`
«из 2 100 ккал», ниже — тонкая плашка «Осталось 460 ккал» на `primaryContainer`.

### MacroChip (новый)
Три в ряд, `weight(1f)`, высота 64 dp, радиус 20 dp, фон `surfaceContainerLow`.
Сверху иконка + подпись `labelSmall`, снизу значение `titleMedium` вида «92 / 120 г».
Прогресс — 4 dp полоска под чипом, цвет `primary`; при перевыполнении — `tertiary`.

### MealRow (переработка `MealRowCard`)
Высота 88 dp, фото 64 dp радиус 18 dp, заголовок `titleMedium` (2 строки), мета
`labelSmall` «08:20 · Блюдо», справа — ккал `titleMedium` и статус-точка 8 dp
(изумруд — готово, янтарь — в обработке, красный — ошибка). Нажатие — ripple по
всей карточке, chevron не нужен.

### SectionCard (переработка)
Белый `surface`, радиус 24 dp, padding 20 dp, заголовок `titleLarge` + опциональный
trailing-экшен. Содержимое — с шагом 12 dp. Вложенные карточки не используются:
внутри — только разделители `outlineVariant` и строки.

### PrimaryButton / SecondaryButton
Высота 56 dp, радиус 18 dp, padding по 24 dp, `labelLarge`. Primary — `primary`/`onPrimary`,
secondary — прозрачный с обводкой `outline`. Нажатие — tonal overlay 8%, disabled — 38%.

### StatusChip
Высота 24 dp, радиус 8 dp, `labelSmall`; пары: готово — `primaryContainer`,
в обработке — `secondaryContainer`, ошибка — `errorContainer`, не еда — `surfaceVariant`.

### SegmentedButton
Высота 40 dp, радиус 12 dp, фон `surfaceContainerLow`, выбранный сегмент — `secondaryContainer`
с галочкой. Используется для типа кадра и пола в анкете.

### NavigationBar
Высота 80 dp, фон `surface`, верхняя граница `outlineVariant`. Активный пункт —
пилюля 64×32 `primaryContainer`, иконка filled `primary`; подпись `labelMedium`.
Три пункта: Сегодня, Календарь, Настройки.

### EmptyState
Круг 96 dp `primaryContainer` с линейной иконкой 40 dp, заголовок `titleLarge`,
подсказка `bodyMedium`, одна кнопка. Никаких «грустных смайлов» — спокойная
иллюстрация и конкретное действие.

### 01 · Сегодня

Порядок чтения сверху вниз: **дата → сколько съедено → из чего → что было → действие**.
Кольцо отвечает на главный вопрос за 0,3 секунды, макросы — за 1 секунду, лента — за 3.
Пустое состояние: иллюстрация тарелки, «Пока пусто» и две кнопки — «Снять» и «Из галереи».
Пока идёт импорт — тонкий `LinearProgressIndicator` под заголовком, без блокирующего диалога.

### 02 · Календарь

Месяц — в белой карточке, а не «на фоне»: сетка читается как объект. Полнота дня
кодируется точкой под числом (не цветом всей ячейки) — так не рябит. Тренд — столбики
высотой от ккал, цвет по полноте дня, пунктир цели. Тап по дню ведёт в «День»,
долгое нажатие — не используется (лишнее открытие).

### 03 · Приём пищи

Фото — hero на всю ширину, 240 dp, радиус 24 dp. Под ним статус-строка и заголовок
«Что на тарелке». Компоненты — строки с граммами, ккал и действиями (карандаш,
корзина); сводка «Итого» — изумрудная карточка с крупной цифрой. Тип кадра —
сегментированный переключатель, а не три отдельных чипа. Удаление карточки — в
overflow-меню сверху, не красной иконкой в шапке.

### 04 · Отчёт дня

Вердикт — первая карточка: крупная цифра и словесный вывод, цвет фона зависит от
вердикта (изумрудный — в цели, персиковый — перебор, нейтральный — мало данных).
Блоки «Энергия / Состав / Режим» — с прогресс-барами к цели, а не только текстом.
Текст ИИ — последняя карточка с кнопкой «Обновить»; он не спорит с цифрами,
потому что цифры выше.

### 05 · Настройки

Профиль — карточка с аватаром-инициалами, целью и кнопкой «Изменить». Дальше —
группы по смыслу: «Подключение» (ключ), «Напоминания» (вечерний отчёт, время),
«Цели», «Данные» и «О приложении». Переключатели — M3 Switch, статус ключа —
точка + текст, не зелёная плашка на весь экран.

### 06 · Съёмка

Камера на весь экран, поверх — только необходимое: назад, заголовок, рамка-подсказка,
затвор 72 dp, галерея, вспышка. Рамка не мешает кадрировать: она тонкая и исчезает
через 2 секунды после первого кадра. После съёмки — сразу назад в ленту, без диалогов
(оставляем текущее поведение).

### 07 · Онбординг: ключ

Первый экран — не форма, а обещание: логотип, «Подключите ИИ», объяснение в две
строки, шаги 1 из 3. Поле ключа — с глазом, ниже два равноправных способа:
буфер и файл. Ошибки — цветной баннер под кнопкой, с человеческим текстом
(«Ключ не подошёл», «Нет сети», «Проблема с сертификатом»).

### 08 · Онбординг: анкета

Прогресс сверху, пол — сегменты, возраст/рост/вес — три поля в ряд (на узких
экранах переносятся в 2+1). Активность — карточки с иконками и подписью, не радио
в столбик. Дефицит — слайдер 15–20% с подсказкой. Итог — изумрудная карточка с
целью и Б/Ж/У, появляется сразу после валидных полей. CTA «Начать» активна только
при валидной анкете.

### 09 · Статистика

Три метрики крупными цифрами, график правок и список «что исправили». Экран
локальный и честный: подпись «данные не отправляются» остаётся.

### 10 · Тёмная тема

Те же роли, инвертированные по светлоте: фон `#101613`, поверхности `#181F1B`,
изумрудный становится светлее (`#7FD8B0`), лайм остаётся акцентом. Фотографии еды
не затемняются — это главный цветовой якорь.

## 7. Внедрение в Compose

Порядок, который даёт максимум эффекта за минимум правок:

1. **Тема.** Заменить `ui/theme/Theme.kt` на полную `ColorScheme` (светлая/тёмная),
   `Typography` с Manrope и `Shapes` (24/28/16). Добавить `FitAppTheme(darkTheme, content)`.
2. **Компоненты.** В `ui/common/Components.kt` добавить `CalorieRing`, `MacroChip`,
   `MealRow`, `ScreenScaffold`, обновить `SectionCard`, `EmptyState`, `StatusChip`.
3. **Экраны.** Переверстать `DayScreen` (hero + лента), `CalendarScreen` (карточка
   месяца + тренд), `MealScreen` (фото-hero + итог), `ReportScreen` (вердикт + бары),
   `SettingsScreen` (профиль + группы), онбординг (шаги + карточки), `CaptureScreen`
   (оверлеи).
4. **Навигация.** `NavigationBar` с пилюлей и правильными иконками; large top app bar
   на «Сегодня»/«Календаре»; shared element для фото блюда.
5. **Полировка.** Анимация кольца, ripple, хаптик на затворе, скелетоны вместо
   `CircularProgressIndicator` на списках, empty/error состояния.

Токены из `tokens.json` переносятся в `Color.kt`/`Type.kt`/`Shape.kt` один в один;
имена ролей совпадают с `MaterialTheme.colorScheme`, поэтому экраны не зависят от
конкретных hex.

### Что осталось за кадром макетов

- Тёмные варианты остальных экранов (схема уже есть, нужны макеты по запросу).
- Состояния загрузки/ошибок для каждого списка (спецификация — в разделе компонентов).
- Планшетная адаптация: две колонки на «Сегодня» (лента + сводка) при ширине ≥ 840 dp.
- Локализация: строки уже вынесены в `strings.xml`, менять только вёрстку.

## 8. Доступность

- Контраст текста — не ниже 4.5:1, крупных чисел — не ниже 3:1 (проверено для
  пар `onSurface/background`, `onPrimary/primary`, `onSecondary/secondary`).
- Тач-цели — минимум 48×48 dp; иконки в списках получают 48 dp hitbox.
- Все изображения блюд — с `contentDescription`; декоративные иконки — `null`.
- Статусы не кодируются только цветом: всегда есть подпись и иконка.
- Шрифт масштабируется (все размеры в sp), длинные названия блюд — 2 строки + ellipsis.
- Анимации отключаются при системном `DurationScale = 0`.

## 10. Как это собрано

- Макеты сгенерированы `qwen-image-3.0-pro` по единому стилевому промпту;
  `generate.py` шлёт запрос в `/chat/completions` (шлюз FitApp не отдаёт
  `/images/generations`), передаёт `parameters.size = 928*1664` и выключает
  автодополнение промпта.
- Генератор хорошо держит композицию и цвет, но путает числа в календарной
  сетке и иногда «ломает» длинные русские абзацы. Поэтому `patch_calendar.py`,
  `patch_screens.py` и `patch_settings.py` точечно перерисовывают эти фрагменты
  шрифтом Manrope: сетка ноября 2026, вердикт и комментарий отчёта, пояснение и
  кнопка онбординга, заголовки статистики, пустая нижняя часть настроек.
- Экран съёмки обрезан по внутренней области телефона, чтобы все десять
  макетов были полноэкранными, без рамки устройства.
- Презентация собирается командой `python3 design/build_gallery.py`; шрифты
  встраиваются base64, поэтому `index.html` открывается офлайн и не зависит
  от системных шрифтов. Для скриншотов есть режим `?static=1` — отключает
  появление по скроллу.

> Важно: макеты — направление и композиция. Точные размеры, отступы,
> состояния и поведение описаны в разделах 2–6 и в `tokens.json`; при
> внедрении источником правды считается спецификация, а не пиксели картинки.
> Иконки на макетах — художественные: в Compose используются
> **Material Symbols Rounded** (24 dp, штрих 1.8), а не нарисованные
> генератором пиктограммы.
